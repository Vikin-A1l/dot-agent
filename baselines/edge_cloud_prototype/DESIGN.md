# 端云协同初版设计

## 范围与依据

以老师截图中三项指标为验收口径：云端 token、任务表现、端到端响应时间。本地 token 单独记录，不计入云端消耗。隐私机制留待后续研究。申请书是项目背景，不把其中设备已部署等表述视为本机事实。

当前部署：AutoDL RTX3080Ti 12GB实例运行 Qwen3-4B-Q4_K_M，llama.cpp提供OpenAI兼容接口。Windows只用于编写和测试。外部API使用DeepSeek官方 `deepseek-flash`，显式关闭思考模式；密钥仅保存在实例私有目录，运行时由安全入口载入环境变量。

## 最短可运行方案

1. Python 标准库实现统一的 OpenAI 兼容聊天接口，支持本地服务和云端服务，避免引入框架依赖。
2. 纯本地、纯云端、整请求规则协同与任务分解协作四种模式使用同一题集、system提示及最终输出限制。dot会增加规划、中间执行和汇总调用。
3. 路由器只使用输入特征，不额外调用模型：较长问题、明确要求证明/多步推理/代码等请求上云，其余走本地。规则为待验证的启发式，不宣称能识别真实难度。
4. 本地调用失败可升级到云端；云端失败如实报错，不伪造模型回复。原型没有答案可信度判定，不保证所有错误答案都能升级。
5. 初版不启用应用答案缓存；模型服务的前缀缓存和云端供应商缓存未控制。缓存、草稿校验和训练路由器作为后续迭代。
6. 输出真实 API usage、总耗时、执行路径、实际模型和错误状态。服务未返回 token 用量时标为未知，禁止按字数估算为真实 token。
7. 内置小型人工题集，固定参考答案和客观评分；测试集仅验证测量流程，不等同 GSM8K/MMLU，也不能证明研究结论。

## 部署选择

采用已部署的llama.cpp服务，模型名称和供应商从配置读取。保留以下早期选型调查作为历史，不再是当前部署要求。

2026-10-02 核对官方资料：`qwen3:4b` 是约 2.5GB 的 Q4_K_M 量化模型，可作为候选；Ollama Windows 文档要求 NVIDIA 驱动至少 551.61，本机 531.61 低于此要求。此本机调查随后被用户指定AutoDL部署所替代，不在本机部署模型。

用户随后明确指定 AutoDL并批准租用，原实例为 `6fcb40b7f5-2694e599`。Windows仅用来编写代码和运行假服务测试；“本地”指同一GPU实例上的小模型服务，区别于外部云端大模型API。

AutoDL实际选型：RTX3080Ti 12GB×1，镜像PyTorch2.8.0/Python3.12/Ubuntu22.04/CUDA12.8；部署官方Qwen3-4B-GGUF量化模型。因固定版本llama.cpp CUDA发布包在Ubuntu24.04构建，改为在目标实例编译固定commit的CUDA服务，不采用本机部署或CPU替代。

独立演示模式必须明显标注模拟。本次已获准使用实例内密钥完成短生成验证及6题四组真实联调，实际证据见验证记录，不能以模型列表认证成功替代生成成功。

## 新增 dot：最小顺序分解协作

云端规划返回严格JSON `{"subtasks":["任务1"]}`，最多4个非空任务。对每个任务复用规则路由，不额外调用分类模型；携带原题和全部已完成结果顺序执行，最后云端汇总。分配记录保留规则原因，实际执行调用逐一追踪。不展示模型内部思维链。

无效计划退化为一次云端整题回答，保留规划消耗；本地执行失败至多升级云端一次；实际云端失败直接停止。每次dot输入的system+user合计最多9000 UTF-8字节，超过时记录事件，不静默截断；尝试一次整题退化，原题仍超限则无外发失败。字节预算不保证满足模型token窗口。

每个请求/调用有唯一ID；评测补充实验ID、题目ID和重复编号。阶段为decompose/execute/aggregate/fallback。所有云端total_tokens只从同一calls列表累计一次，输入/输出usage及本地token另存，未知为null。完整耗时包括调度及本地推理；阶段调用耗时之和不代表完整墙钟时间。

这只是参考DoT的简化原型，不包含复杂依赖图、并行调度、训练、工具执行或多轮辩论。

## 文件计划

- `README.md`：安装、配置、演示、指标口径与已知限制。
- `config.example.json` / `config.deepseek.example.json`：仅本地 / 四模式非敏感配置，密钥仅引用环境变量名称。
- `edge_cloud/`：配置、HTTP 客户端、规则路由、执行器、评测及 CLI。
- `data/smoke.jsonl`：保留原12题；`data/dot_smoke.jsonl`：独立计算答案的6道组合题，哈希在运行前冻结。
- `tests/`：本地 HTTP 假服务验证真实请求协议、路由、降级、指标缺失和报错。
- `reports/`：实测与模拟分开标记，不保存 API key 或服务器错误正文。

## 验收

- 本地假服务测试通过，覆盖四种模式、HTTP格式、顺序/前置结果、边界计划、预算、usage缺失、有限升级退化。
- CLI 可以运行演示并导出 JSONL 与汇总；模拟数据必须显式标记，不能作为节省比例证据。
- 四组在同一题集执行；报告准确率、云端token、平均与P50/P95完整时延、成功率、升级及退化次数，单列分解和汇总开销。未知token不能汇总成零。
- 不承诺协同一定比纯云端快；失败升级会增加时延，需要真实对照实验检验。
