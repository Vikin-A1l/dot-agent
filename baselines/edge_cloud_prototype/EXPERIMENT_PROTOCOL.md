# 简化 DoT 首轮演示协议（运行前固定）

日期：2026-10-02。目的：展示任务分解协作及四组计量流程；不以小样本结果证明研究收益。

- 数据：`data/dot_smoke.jsonl`，6题，SHA256 `dd9f8cb480e8ae8d7a3ba0ae90a8b0a16518a9fd3af1eca8f7f5902354479638`。
- 独立答案核对：`python scripts/check_dot_dataset.py`，使用整数算术与组合穷举，无模型参与。
- 参考答案：d01=42；d02=(12×8+5×14)−20=146；d03=300−ceil(48×2/6)×15=60；d04=A144元/B122元，选B；d05=60−5−8−4=43；d06=AB77元/评分9.5、AC63元/9.1、BC70元/9.4，选AB。
- 评分：沿用 normalized_exact_match，仅宽容首尾空白、全半角、大小写和句末标点；附带解释仍算不匹配。请求失败计错。
- 模式：local、cloud、hybrid、dot；同6题、各1次，共24完整请求；按题号轮换执行顺序。
- 本地：AutoDL Qwen3-4B-Q4_K_M / qwen-local，既有4096上下文、单并发、非思考服务。
- 云端：DeepSeek官方 `deepseek-flash`，显式 `thinking.type=disabled`，各组一致。模型别名可能随供应商更新，记录实际响应model字段与时间，不声称固定权重。
- 普通调用：temperature=0，max_tokens=512；规划JSON调用max_tokens=512。dot最多4子任务，输入system+user上限9000 UTF-8字节（不是模型token窗口）。
- 上下文传递：顺序执行，携带完整前置结果；超过工程预算时记录并退化，不静默截断。
- 开销：dot分解、云端执行、升级、汇总及退化全部计量；本地tokens单独列出。API未返回usage记未知，不按字符估算token。
- 预检：先一个至多32输出token的cloud短请求，成功且usage完整后再本地预热一次。这两次调用单独保留并统计实际云端用量，不混入四组准确率/时延。
- 规模上限：在每个本地子任务只升级一次、每请求至多一次退化的约束下，四组加预检最多49次实际云端调用；不自动重复整轮实验。
- 时延：客户端位于AutoDL，测开始调度至最终返回；包含网络、完整生成和本地推理，排除模型启动、SSH传输和上述预热。
- 缓存：应用不缓存答案；llama.cpp前缀KV缓存和供应商缓存不受本实验控制，可能影响耗时。按真实API usage计token，token总数不等于实际账单金额。
- 输出：原始逐请求JSONL、汇总JSON、协议与源码/配置/题集哈希、预检结果、独立核对记录。使用新目录，拒绝覆盖历史。
- 报告所有题目、错误和退化。不得按结果修改题集、评分或参数；若代码错误确需重跑，保留旧结果并写明原因。

限制：6题×1次不能给出稳定P95或统计显著性，也不代表GSM8K/MMLU。即使dot更慢或token更多，也如实报告。
