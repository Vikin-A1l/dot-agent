# 统一端云协作入口

本版本在团队 dot-agent 上增量接入资料问答：原有分类、拆任务、依赖调度和本地/云端分工继续使用；带资料的问题采用证据选择、原文回取和云端回答。模型权重没有训练或合并。

## 快速体验

在本工作区根目录运行：

```powershell
python -m dot_agent.server --demo --host 127.0.0.1 --port 8765
```

浏览器打开 http://127.0.0.1:8765 。点击“资料问答示例”，也可在“附带资料”中粘贴文本，每段之间留一个空行。系统自动生成 source-1、source-2 等编号。切换到“本地小模型选择”可以体验另一条流程；点击普通问题示例会清空资料并回到原任务框架。

--demo 显式创建演示客户端，即使进程已有真实模型环境变量也不会读取它们。演示回答、token 和时间不能用于证明真实模型效果。Ctrl+C 关闭本地服务。

真实接入继续使用既有 docs/AUTODL_MAINLINE.md 的网关配置，不修改远端密钥存储或部署目录。去掉 --demo 才会按现有配置选择后端；本次没有做真实模型验收。

## 同一个入口如何分工

| 用户输入 | 流程 |
|---|---|
| 只有问题 | 原分类、快速通道或任务拆分流程 |
| 问题加资料，默认方式 | BM25 选原文 → 程序取回证据 → 云端回答 |
| 问题加资料，本地选择 | 本地模型只报证据编号 → 程序取回原文 → 云端回答 |

资料流程不再额外执行通用任务拆分。带资料请求绕过当前仅按问题匹配的缓存，避免换资料返回旧答案。在线普通请求仍沿用旧缓存行为。

程序校验来源编号、引用范围和输出格式；它不能自动证明答案符合事实。模型证据不足时可返回固定弃答形式：{"answer":"证据不足","citations":[]}。

资料选择或回答契约失败，最多执行一次流程级全文云端回退。账本写入失败属于工程故障，会立即停止后续模型调用，并标记账本不完整。网关原有瞬态重试仍逐次计量；没有云端失败后静默改成本地回答。全文请求超出字节预算时明确失败，不静默截掉资料。字节预算不是 tokenizer 的上下文长度保证，真实服务的 context 仍需独立确认。

## JSON API

原请求 {"query":"问题"} 保持兼容。新增可选 sources 和 selector：

```json
{
  "query": "报名截止时间是什么？",
  "sources": [
    {"source_id": "location", "text": "演示活动地点在教学楼。"},
    {"source_id": "deadline", "text": "报名截止时间是周五17点。"}
  ],
  "selector": "bm25"
}
```

API 的 selector 为 bm25 或 local，默认 bm25。提供 sources 时必须为非空列表，来源编号不能重复。表格行依赖表头时，可在 JSON 的来源中声明 requires: ["header-id"]；程序会同时回取对应原文，仍受证据预算约束。

返回增加 success、error、provided_sources、citations。provided_sources 表示该次答案请求所用的来源，citations 只列模型实际返回且属于该请求来源的引用，两者不能混为一谈。未完成的资料流程返回 HTTP 502，仍携带本次已有计量和决策轨迹；输入错误在调用模型前返回 HTTP 400。

HTTP 正文上限 1 MiB；最多 128 个来源、来源序列化后最多 256000 字节；所选证据最多 8 条、16000 字节；完整模型提示最多 48000 字节。本地选择输出最多 128 token，云端答案最多 512 token。这里只接受调用方已提供的文本，不新增 PDF/Word 解析。

## 单独比较四条资料路线

```powershell
python eval/evidence_runner.py --demo --output reports/my-evidence-demo
```

输出目录必须不存在。full 为全文云端、rule 为固定词重合、bm25 为 BM25 检索、local 为本地编号选择。每题轮换模式顺序，所有调用走相同计量出口，资料流程使用相同云端回答契约并关闭应用缓存。full 自身失败后不会再把同一全文请求当成回退重做。

results.jsonl 保留每个单元的结果、失败、轨迹、已提供来源、引用和计量；summary.json 分模式汇总。失败保留在单元分母内，缺失 usage 保留未知，不把已知小计冒充完整用量。模拟运行标记 usage_kind=simulated，不计算答案质量分。真实运行的 normalized exact match 仅适合具有固定参考答案的诊断题，不等于 QASPER 官方 F1 或 FinQA 正式评分。

真实对照需要显式 --real 和自己的 --dataset，且两个后端都必须是真实客户端。入口不会自动执行预热；如需预热须单独执行并记账。本次提供的 evidence_smoke.jsonl 是两条合成工程题，不能作为科研验证集；原 Stage 5 冻结样本、launcher 和结果均未修改。
